Machine: Windows 11 Home 10.0.26200, AMD Ryzen 7 5700X (8C/16T), 16 GB RAM, NVIDIA GeForce RTX 5060 (8 GB), 1920×1080 @ 300 Hz. All tests that create data used throwaway folders (`SHADOW_DATA_DIR` / temp dirs). The real `%APPDATA%\.minecraft` and other launchers' folders were only read.

What the Rust suite covers (temp dirs + local mock HTTP servers; never the real install):

| Requirement | Tests |
|---|---|
| Install discovery | launcher profiles with custom `gameDir`, versions/loader detection, mods/packs/worlds; account files never read |
| Version metadata parsing | rules (os/arch/version/features), maven paths, argument expansion, child/parent merge, legacy JSON |
| Profile create / delete safeguards / isolation | worlds preserved on delete, external folders untouched, duplicate with/without worlds, profiles don't share mods |
| Mod install / remove / restore | resolver → download → hash → metadata verify → install; enable/disable; remove to backup; restore; traversal names rejected |
| Dependency resolution & compatibility | required/optional deps, already-installed, wrong MC version blocked with suggestions, Sodium↔OptiFabric conflict, vanilla refuses mods, jar metadata contradicting the API ⇒ nothing installed |
| Download interruption / resume | connection cut mid-file ⇒ resumed with HTTP Range; verified files skipped; hash mismatch ⇒ no file left; cancel keeps `.part`, retry completes; non-HTTPS refused |
| Cache validation | TTL cache hit, stale-cache fallback when the server fails, corrupt cache entry ignored |
| Path traversal | `..`, absolute, drive letters, ADS, reserved names; malicious `.mrpack` entries and overrides skipped |
| Java selection | exact major, Mojang component preferred, Java 8 for legacy, newer fallback with note, too-old override refused |
| Memory validation | never allocates all RAM, workload sizing, invalid combinations rejected |
| Auth error handling | device-code flow, XSTS "no Xbox profile", "does not own Minecraft", success with DPAPI-encrypted tokens, removal, offline validation |
| Launch failures | fake Java that exits ⇒ reported as failed with diagnosis (never "running"); confirmed start ⇒ running → exited "ok"; tokens redacted in game logs |
| Config backups | options.txt unknown keys preserved, backup + original kept, restore, legacy formats |
| Modpack install | .mrpack install/update (keeps worlds + personal options) /export; CurseForge pack needs key, manual-download list for opted-out files; Forge packs refused |
| Built-in mods | embedded jar hashes match pins; install with Fabric API dependency; skipped (not forced) where no build exists; cannot be disabled or removed |
| Skins | PNG validation (64×64/64×32 only), library create/rename/delete, local skin resource pack contents + options.txt activation that preserves other keys, player lookup via mocked Mojang APIs, unknown player, offline accounts refused for upload |

Two genuine bugs were found by these tests and fixed: a launch whose output pipe closed was briefly treated as "started", and two launches in the same second overwrote each other's log file.
